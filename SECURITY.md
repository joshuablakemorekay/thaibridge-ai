# Security

How ThaiBridge AI protects learners' accounts, payments and data, and what it costs to run.
Also covers how to report a problem, and the known gaps still on the list.

*Last checked against the code: 13 November 2026.*

---

## Reporting a problem

If you find a security issue, please **email joshua@smoald.com** rather than opening a
public GitHub issue. Include what you found, how to reproduce it, and which page or route
is affected. I read every message myself and will reply as soon as I can.

Please don't test against other people's accounts or try to access data that isn't yours.

## Secrets

- **Every secret comes from an environment variable**: the Anthropic key, the Flask secret
  key, Stripe and PayPal keys, the Resend key, the database URL, the developer password and
  the Monk Mode codes. None of them are in the code. `.env` and the local database are
  listed in `.gitignore`.
- **The app refuses to start** without `ANTHROPIC_API_KEY` or `FLASK_SECRET_KEY`, rather
  than running half-configured.
- **On Render**, `FLASK_SECRET_KEY` is generated by Render itself, and every other secret
  is marked `sync: false` in `render.yaml`, so it's only ever typed into the dashboard.
- **CI uses placeholders** that could never be mistaken for real keys, and no payment or
  database credentials at all.

## Accounts and sign-in

- **Passwords are hashed** with Werkzeug and never stored as typed. New passwords need at
  least 8 characters, including a letter and a number.
- **Flask-Login** keeps only the account id in the signed session cookie and loads the
  account from the database on every request.
- **A new password signs out every other device.** The id in the login cookie includes a
  session version, and changing the password bumps it, so older cookies stop working.
- **Password resets** use a signed link that expires in 30 minutes and only works once (it
  carries a fingerprint of the current password hash). The reply is the same whether or
  not the email has an account, and the email is sent in the background, so the response
  time doesn't give that away either. The owner gets a "your password was changed" email.
- **Rate limits** (Flask-Limiter) sit on log-in, sign-up, password resets and the
  developer log-in, so passwords can't be guessed at speed. Visitors
  are identified by Cloudflare's `CF-Connecting-IP` header, so the limit applies to each
  real visitor rather than to the proxy everyone arrives through.

## Developer mode

- **Off unless a password is configured.** There is no default password. Blank or missing
  means the route is switched off. A test pins this.
- Developer-only pages (such as `/reviews/private`) answer **404 Not Found** to everyone
  else, so they don't even confirm they exist.

## Payments and paid access

- **Card details never reach ThaiBridge.** Payment happens on Stripe's (or PayPal's) own
  pages.
- **The Stripe webhook checks Stripe's signature** on every event before acting on it.
  Paid access is granted only there (and by the matching success-page check), never by
  the browser.
- **Access is read from the database.** The tier, the Instant Access Pass, the earned
  unlock and alphabet completion live on the `User` row. The session cookie only holds a
  working copy, and keys that grant anything are never saved back from it. Editing a
  cookie can't unlock a page.
- **No double charges or double records.** Each payment's Stripe or PayPal reference is
  unique in the `payments` table, so a webhook delivered twice is recorded once.
- **XP can't be faked.** Each drill question's answer is signed with an HMAC (a
  tamper-proof fingerprint made with the secret key). The browser never sees the answer,
  can't claim XP for a wrong one, and drill XP has a daily cap.

## The AI tutor and its costs

- **The AI routes are rate limited** per visitor, on top of each plan's daily message
  allowance. The allowance is counted in the session cookie, so the rate limit is the
  real floor for anyone who clears cookies or uses a script. Pro's fair-use ceiling of 75
  messages a day is counted from the database, so clearing cookies doesn't reset it.
- **The Anthropic account has a hard monthly spending limit** and its own API key, so a bad
  day can't run up an unlimited bill, and the key can be revoked on its own. If the credit
  runs out, the tutor shows a calm "resting" message instead of an error.
- **Photo uploads** (Translator mode, Pro only) are limited to JPEG, PNG and WebP, checked
  by the file's actual contents rather than its name, and capped at 4 MB. Photos are sent
  to Claude and never stored.
- **Conversations are never stored.** `ai_usage` records tokens, model, plan and outcome so
  costs can be measured. It never stores what anyone asked or what the tutor replied.

## Web safety

- **Forms that change things take JSON.** Most actions (log-in, quizzes, reviews, the
  learning path) only accept `Content-Type: application/json`. A form on another website
  can't send that without the browser checking with ThaiBridge first, which blocks
  forged requests from other sites.
- **Templates escape everything by default** (Jinja2 autoescaping). The few places that
  output raw HTML (`|safe`) only use text written by the developer in the code, never
  anything a user typed.
- **Database queries go through SQLAlchemy** with parameters. The only raw SQL adds
  missing columns at start-up, using fixed names from the code.
- **The app only redirects to its own pages.** Where it sends someone back to the page
  they came from (after claiming the earned unlock), it checks the address belongs to
  ThaiBridge first.
- **The old domain** (`thaibridge-ai.smoald.com`) redirects permanently to
  `thaibridge.smoald.com`.
- **Tracking needs consent.** The Meta advertising cookie only loads if the visitor clicks
  Accept, and declining changes nothing about the site.

## Data and privacy

What's kept and why is set out for learners on the [privacy page](https://thaibridge.smoald.com/privacy).
In short: account details, learning progress, plan and payment records, AI usage counts
(not content) and, if a learner chooses to leave one, their review. Accounts are deleted
on request by email. Payment records are kept as long as UK tax law requires.

## Known gaps

Honest list of what isn't done yet, roughly in priority order:

1. **Cookie settings aren't set explicitly.** `SESSION_COOKIE_SECURE` and
   `SESSION_COOKIE_SAMESITE` (and the remember-me equivalents) use Flask's defaults. The site
   is HTTPS-only behind Cloudflare and modern browsers treat cookies as `SameSite=Lax`
   anyway, but the app should say so itself instead of relying on that.
2. **A few older routes take ordinary form posts** (developer log-in, Monk Mode codes, the
   dāna amount, cancelling a subscription), so they don't get the JSON protection above.
   They rely on the browser's `SameSite=Lax` default today. Setting the cookie options in
   point 1 closes this. Moving them to JSON (or adding CSRF tokens) would close it fully.
3. **No security headers yet**, such as `Content-Security-Policy`, `X-Frame-Options` /
   `frame-ancestors`, or `Strict-Transport-Security`.
4. **The developer password is hashed with plain SHA-256** for comparison. It's only ever
   read from an environment variable and the route is rate limited, but a constant-time
   comparison and a slow hash (as used for learners' passwords) would be better practice.
5. **Monk Mode codes aren't rate limited.** `/monk-mode` checks a code without the limit the
   log-in routes have, so codes could be guessed at speed. The codes only open the monk
   learning track (not the paywall), but the route should get the same limit as the
   developer log-in.
6. **No self-service account deletion.** It's done by email today.
